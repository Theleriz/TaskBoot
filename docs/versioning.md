# Версии Task Tracker

Версия записывается как `vA.B.C`, например `v2.1.3`. Каждая цифра отвечает за свой масштаб изменений.

| Цифра | Пример | Когда увеличивается |
|---|---|---|
| **A — старшая** | `v1.x.x` → `v2.0.0` | Глобальные изменения проекта: полная переработка дизайна; появление или смена больших технологий и платформ; смена курса проекта — пересмотр будущих глобальных планов |
| **B — средняя** | `v2.0.x` → `v2.1.0` | Новые заметные функции, которые пользователь видит сразу: новая вкладка, новый инструмент, новая крупная возможность |
| **C — младшая** | `v2.1.0` → `v2.1.1` | Патчи: исправления ошибок, мелкие доработки, изменения логики и всё, что почти не заметно в интерфейсе |

При увеличении цифры все цифры правее неё обнуляются: после `v2.3.4` новая функция даёт `v2.4.0`, глобальное изменение — `v3.0.0`.

## Предварительные выпуски

Версию, которая ещё проверяется, помечают суффиксом: `v2.1.0-beta.1`, `v2.1.0-rc.1`. Такие теги публикуются на GitHub как pre-release и не становятся «последним выпуском». Готовая версия выходит без суффикса.

## История старших версий

| Версия | Что это | Тег |
|---|---|---|
| v1 | Нативное приложение для Windows (WPF) и одностраничная веб-версия в одном `index.html` | выпуск `v1.0.0-beta` на теге `Beta`; последний код v1 — тег `wpf-legacy` |
| v2 | Смена парадигмы: кроссплатформенное веб-приложение (React + TypeScript) как основная кодовая база и тонкая оболочка WebView2 для Windows ([архитектура](architecture.md)) | `v2.0.0` |

## Как выпустить версию

Выпуск делается только из `main` с зелёным CI ([CONTRIBUTING.md](../CONTRIBUTING.md)).

1. Решить, какая цифра растёт, по таблице выше.
2. Записать номер в проект (без `v`):
   - `web/`: `npm version 2.1.0 --no-git-tag-version` — обновит `package.json` и `package-lock.json`;
   - `win32/TaskTracker.csproj`: поле `<Version>`.
3. Закоммитить и отправить изменения.
4. Поставить тег и отправить его:

   ```bash
   git tag -a v2.1.0 -m "Task Tracker 2.1.0"
   ```

   ```bash
   git push origin v2.1.0
   ```

5. Workflow `release.yml` проверит и соберёт проект и создаст GitHub Release с архивами `TaskTracker-2.1.0-windows.zip` и `TaskTracker-2.1.0-web.zip`. Номер версии в `TaskTracker.exe` берётся из тега.

## Версия данных — отдельно

Номер схемы данных (`schemaVersion` в `data.json` и в хранилище браузера) не связан с версией приложения. Он растёт, только когда меняется формат хранимых данных, и обрабатывается миграциями (`web/src/data/schema.ts`). Новая версия приложения может не менять схему, а смена схемы обычно выходит в средней или старшей версии.
