# Дорожная карта Task Tracker

Редакция от 2026-10-20. Учитывает новые правила ТЗ: внешние зависимости и сборка разрешены (базовое ТЗ, п. 4 и 4.1).

## Принципы

- **Офлайн по умолчанию.** Всё, кроме AI-функций, работает без интернета; библиотеки входят в сборку (N-03).
- **Данные пользователя остаются у пользователя.** Наружу (API распознавания речи, языковой модели, облачного TTS) данные уходят только по явному действию, и интерфейс об этом предупреждает.
- **Ключи — свои у каждого пользователя (BYOK).** Ключ API вводится в настройках или в `.env.local` и никогда не попадает в репозиторий (`docs/secrets-policy.md`). Веб-версия без бэкенда может работать только с ключом самого пользователя; общий ключ потребовал бы своего бэкенда-прокси.
- **Лицензии** в таблицах указаны на момент составления. Перед подключением их нужно сверить (D-01) и внести в `THIRD_PARTY_NOTICES.md` (D-03).

## Главное архитектурное решение

**Принято 2026-10-20: вариант A.** Веб — основная кодовая база; нативное приложение для Windows — оболочка на WebView2.

Почти все новые фичи — это богатый интерфейс (редактор заметок, формулы, доска, PDF). В вебе для них есть зрелые библиотеки; в WPF их почти нет или они другие. Если писать каждую фичу дважды, объём работы удвоится.

| Вариант | Как | Плюсы | Минусы |
|---|---|---|---|
| **A. Гибрид (выбран)** | Веб-интерфейс — основная кодовая база. Нативное приложение — оболочка WPF с WebView2 (встроенный движок Edge, предустановлен в Windows 11), которая показывает этот интерфейс и добавляет системное: трей, уведомления, голос, файлы, горячие клавиши | Каждая фича пишется один раз; веб и Windows всегда равны | Нативная версия перестаёт быть «чистым WPF»; нужен NuGet-пакет WebView2 |
| B. Две кодовые базы | Как сейчас: WPF и веб отдельно | Максимально «нативный» вид | Каждую фичу писать дважды; для части фич в WPF нет библиотек |
| C. Веб + обёртка | Tauri или Electron вместо WPF | Кросс-платформенный десктоп (Windows, macOS, Linux) | Уходим от WPF; Electron тяжёлый, Tauri требует Rust |

Сопутствующие решения:
- **Веб-версия переходит на сборку** (например, Vite + npm): модули вместо одного файла, зависимости через `package.json` и lock-файл.
- **Нативная сборка** переходит со встроенного `csc` (C# 5) на .NET SDK. Это даст NuGet, современный C# и упростит подключение библиотек. Требует установки .NET SDK на машине разработчика (пользователям ничего ставить не нужно).

## Фичи

### 1. Пространства знаний (заметки в папках, поиск, RegEx, LaTeX)

Дерево папок, заметки в Markdown с формулами, полнотекстовый поиск и поиск регулярными выражениями, связи заметок с задачами.

| | Веб | Нативная (без гибрида) |
|---|---|---|
| Редактор | CodeMirror 6 (MIT) | обычный TextBox / AvalonEdit |
| Markdown | markdown-it (MIT) | Markdig (BSD-2) |
| Формулы | KaTeX (MIT) | WpfMath (MIT) — только формулы, без общего рендера |
| Поиск | MiniSearch (MIT) + `RegExp` | встроенный `Regex` |
| Хранение | IndexedDB | файлы `.md` в папке пользователя |

**Сложность:** средняя (в гибриде — только веб-часть). **MVP:** папки, Markdown, поиск, RegEx; KaTeX сразу. Нативный вариант без гибрида заметно слабее (нет общего рендера Markdown + формул), это главный аргумент за вариант A.

### 2. Карточки как в Anki

Колоды, карточки «вопрос–ответ» и cloze, интервальные повторения, создание карточки из выделенного текста заметки.

| | Веб | Нативная |
|---|---|---|
| Планировщик | ts-fsrs (MIT), алгоритм FSRS | порт FSRS на C# или SM-2 своими силами (это ~100 строк) |
| Рендер карточек | тот же Markdown + KaTeX | как в п. 1 |

**Сложность:** низкая–средняя. **Хорошее первое задание после решения по архитектуре:** мало интерфейса, много пользы, опирается на п. 1. Позже — импорт колод Anki (`.apkg` — это zip с SQLite, потребует sql.js).

### 3. Текст в речь

Озвучка заметок, описаний задач, выделенного текста.

| | Веб | Нативная |
|---|---|---|
| Базовый | `speechSynthesis` (встроен в браузер) | `System.Speech` / голоса Windows |
| Качественный офлайн | нейросетевой TTS в браузере (например, модели Piper через ONNX) — проверить лицензию | Piper как отдельный процесс — проверить лицензию |
| Облачный | API облачного TTS (BYOK) | то же |

**Сложность:** низкая для базового варианта. Русский системный голос есть, если в Windows установлен русский языковой пакет.

### 4. Аудирование книг

Импорт TXT / EPUB / PDF (текстовый слой), чтение вслух с закладкой, скоростью и подсветкой текущего предложения.

| | Веб | Нативная |
|---|---|---|
| EPUB | epub.js — проверить лицензию | VersOne.Epub — проверить лицензию |
| PDF-текст | pdf.js (Apache-2.0) | см. п. 7 |
| Озвучка | п. 3 | п. 3 |

**Сложность:** средняя. Качество зависит от голоса: системный звучит механически, для книг лучше нейросетевой (п. 3).

### 5. Речь в текст

Диктовка заметок и задач.

| | Веб | Нативная |
|---|---|---|
| Быстрый вариант | Web Speech API (только Chrome/Edge, звук уходит на серверы Google/Microsoft) | системный ввод Windows 11 (Win+H) работает в любом поле уже сейчас |
| Качественный офлайн | Whisper в браузере (transformers.js, Apache-2.0; нужна мощная видеокарта/WebGPU) | whisper.cpp (MIT) через Whisper.net (MIT) |
| Облачный | API распознавания (BYOK) | то же |

**Сложность:** средняя. Офлайн-модели весят от десятков мегабайт до гигабайтов — скачивать по запросу, а не класть в сборку.

### 6. Whiteboard

Бесконечная доска: фигуры, стрелки, текст, рукописный ввод, вставка карточек задач и заметок.

| | Веб | Нативная |
|---|---|---|
| Доска | Excalidraw (MIT) — готовая доска с экспортом в PNG/SVG | `InkCanvas` (встроен в WPF) — рисование и стилус, без фигур и стрелок |

**Сложность:** низкая с Excalidraw (встраивание + хранение сцен), высокая для полноценной доски на WPF. Ещё один аргумент за гибрид.

### 7. Работа с PDF

Ставлю реалистичный объём по шагам, а не «полноценный редактор».

1. Просмотр, поиск по тексту, выделения и комментарии, связанные с заметками.
2. Склейка, разделение, поворот, удаление страниц.
3. Заполнение форм, подпись изображением.

| | Веб | Нативная |
|---|---|---|
| Просмотр | pdf.js (Apache-2.0) | WebView2 / PDFium-обёртки — проверить лицензии |
| Изменение | pdf-lib (MIT) | PdfSharp (MIT) |

**Сложность:** средняя для шагов 1–2, высокая для 3. Редактирование самого текста внутри PDF — вне объёма (это задача профессиональных редакторов).

### 8. Саммари встреч

Запись встречи → расшифровка → краткое содержание, решения, задачи (сразу в TODO с квадрантом).

- **Запись звука:** микрофон в обеих версиях; звук других участников — системный звук через NAudio (MIT, WASAPI loopback) в нативной, захват вкладки в Chrome/Edge в веб.
- **Расшифровка:** п. 5 (лучше Whisper).
- **Саммари:** языковая модель по API, например Claude API (Claude Haiku 5.5 — дёшево и быстро, Claude Sonnet 5.5 — точнее). Ключ — BYOK.
- **Риски:** приватность (записи встреч уходят в облако — нужно явное согласие и предупреждение, а участников встречи нужно уведомлять о записи), стоимость длинных встреч, разделение по говорящим (diarization) — отдельная сложная задача, в MVP не входит.

**Сложность:** высокая. **MVP:** загрузка готовой аудиозаписи или текста расшифровки → саммари и список задач.

### 9. Аудиопересказ в стиле NotebookLM

Из выбранных заметок, PDF или книги генерируется сценарий диалога двух ведущих, который озвучивается двумя голосами.

- **Сценарий:** языковая модель (п. 8), промпт с ограничением длины и ссылками на источники.
- **Озвучка:** нужен качественный нейросетевой TTS с двумя голосами (облачный, BYOK); системные голоса для этого не годятся.
- **Режим «онлайн»:** потоковая генерация — сценарий по частям, озвучка по мере готовности.

**Сложность:** очень высокая, зависит от п. 3 и п. 8. Делать последним.
