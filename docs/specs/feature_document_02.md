# Техническое задание: расширение Task Tracker — вкладка «Рабочее пространство» и расширенные карточки задач

## 1. Общие сведения

**Базовый проект:** Task Tracker (см. базовое ТЗ [`task_manager_description.md`](task_manager_description.md) в этой же папке) — веб-приложение без бэкенда и нативное приложение для Windows.

**Цель расширения:** добавить в приложение персональное рабочее пространство для заметок и секретов, а также расширить модель задачи, чтобы у каждой карточки появилось содержимое — описание, произвольный текст, чек-лист и ссылки.

**Ключевой принцип, сохраняемый из базового ТЗ:** задачи остаются едиными. Новые поля задачи отображаются и редактируются во всех вкладках, где задача присутствует, без дублирования данных.

**Форм-фактор:** десктоп-браузер, адаптив ≤ 720px, без изменений.

## 2. Новые термины

| Термин | Значение |
|---|---|
| Рабочее пространство | Новая вкладка с заметками и секретами |
| Заметка | Свободный текстовый блок в рабочем пространстве |
| Секрет | Запись с конфиденциальным значением (токен, пароль), скрытая по умолчанию |
| Детали задачи | Расширенное содержимое карточки: описание, текст, чек-лист, ссылки |
| Чек-лист | Список подпунктов задачи с отметкой выполнения |
| Ссылка | URL, прикреплённый к задаче |

## 3. Функциональные требования

### 3.1. Новая вкладка «Рабочее пространство»

| ID | Требование | Приоритет |
|---|---|---|
| F-60 | В шапке появляется четвёртая вкладка «Пространство» рядом с существующими | Обязательно |
| F-61 | Вкладка содержит две секции: «Заметки» и «Секреты» | Обязательно |
| F-62 | Пользователь может создать заметку: ввести заголовок и текст, подтвердить | Обязательно |
| F-63 | Заметка отображается в списке; по клику раскрывается для просмотра/редактирования | Обязательно |
| F-64 | Пользователь может редактировать и удалять заметки | Обязательно |
| F-65 | Пользователь может создать секрет: название и значение | Обязательно |
| F-66 | Значение секрета по умолчанию скрыто (маскируется), показывается по кнопке «Показать» | Обязательно |
| F-67 | Пользователь может редактировать и удалять секреты | Обязательно |
| F-68 | Заметки и секреты сохраняются между перезагрузками страницы | Обязательно |
| F-69 | Пустые секции отображают плейсхолдер «пусто» | Желательно |
| F-70 | Копирование значения секрета в буфер обмена одной кнопкой | Желательно |

**Ограничения по секретам (важно зафиксировать в ТЗ):**
- Значения секретов хранятся в хранилище браузера (с v2.1.0 — IndexedDB, прежде — `localStorage`) или в `data.json` оболочки в **открытом виде** (как и всё остальное в приложении). Это **не** менеджер паролей с шифрованием.
- В интерфейсе должно быть явное предупреждение об этом (например, подпись под секцией «Секреты»).
- Если требуется реальное шифрование — это отдельная задача (см. п. 9), в текущий объём не входит.

## 5. Модель данных

### 5.1. Изменения в задаче

К существующей структуре добавляются поля:

```js
{
  id: string,
  title: string,
  quadrant: 'q1'|'q2'|'q3'|'q4',
  status: 'todo'|'doing'|'done',
  createdAt: number,

  // новые поля
  description: string,          // многострочное описание, по умолчанию ""
  checklist: [                  // чек-лист, по умолчанию []
    { id: string, text: string, done: boolean }
  ],
  links: [                      // ссылки, по умолчанию []
    { id: string, url: string, label: string }
  ]
}
